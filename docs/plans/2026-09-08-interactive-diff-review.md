# 交互式差异审核设计与验证记录

日期：2026-09-08

对应实施计划：Task 19。

## 目标与边界

本阶段把桌面应用壳接到真实、只读的快照比较工作流，提供目录选择、扫描进度、取消、差异统计、风险标记、传输量估算、筛选和审核列表。完整 `DiffSet` 会保留给下一阶段使用，但 Task 19 不生成、写入、应用或回滚补丁；“生成补丁”按钮保持禁用并明确标注 Task 20。

默认扫描规则继续包含 `.obsidian/plugins/**` 和 `.obsidian/themes/**`，排除 `.trash/**`。旧快照与新快照必须是两个独立目录：路径相同或一个目录包含另一个目录时，在任何扫描开始前阻断。

## 模块划分

Application 新增 `CompareWorkflow`，负责：

1. 使用同一 `SnapshotRuleSet` 扫描基线与目标。
2. 报告基线扫描、目标扫描、差异分类和完成阶段。
3. 生成确定性 `DiffSet`。
4. 统计 Added、Modified、Deleted、Renamed、Unchanged、传输文件数、传输字节和风险项。

`SnapshotScanner` 增加可选进度端口，在一个纳入规则的条目完成处理并加入 inventory 后报告条目数和当前相对路径。原有重载保持兼容，Application 不引用 Avalonia。

Desktop 通过 `ICompareService` 和 `IFolderPicker` 使用工作流。实际目录选择由 Avalonia `StorageProvider.OpenFolderPickerAsync` 提供，避免 Windows 专用 API。ViewModel 不直接访问文件系统、计算哈希或构造 Diff。

## 状态机与验证边界

比较会话状态包括：

- `Empty`：尚未选择完整路径。
- `Ready`：两个路径已提供，可以开始比较。
- `ScanningBaseline`：只读扫描旧快照。
- `ScanningTarget`：只读扫描新快照。
- `Comparing`：两个完整 inventory 已形成，正在分类差异。
- `Completed`：完整结果可审核；内容一致时显示无需补丁。
- `Cancelled`：当前比较停止，不保留半成品结果，路径仍保留。
- `Error`：不产生可审核结果，路径仍保留，并显示可读错误。

扫描总量在开始前未知，因此使用不确定进度条，同时展示已完成条目数和当前相对路径。取消令牌按比较会话独立创建，只影响当前比较。新的比较会清除旧结果、旧错误和筛选状态。

## 风险与传输估算

以下变化标记为风险项：

- 删除。
- 重命名。
- `.obsidian/**` 下的变化。
- 同一路径同时出现 Delete 与 Add 的类型变化。

传输估算只计算 Added 和 Modified 文件的目标指纹长度。目录不计字节，Rename 在当前 manifest 语义下不携带 payload。筛选仅作用于桌面审核集合，不改变底层 `DiffSet`；审核列表不显示 Unchanged，但完整比较结果仍保留它们。

## 界面实现

比较页延续“本地工具台”视觉：深墨侧栏、暖灰工作区和青绿色状态强调。页面从上到下分为：

1. 两个独立目录的路径输入与跨平台选择按钮。
2. 阶段状态、当前路径、已处理条目数和取消操作。
3. 新增、修改、删除、重命名、预计传输和风险统计。
4. 全部/类型/风险筛选和变化审核列表。
5. 内容一致空态、可恢复错误态，以及禁用的下一阶段按钮。

## 自动化与视觉验证

Application 测试覆盖同规则双扫描、阶段顺序、差异统计、传输字节、风险统计、相同/嵌套路径阻断和取消不返回半成品结果。

Desktop ViewModel 测试覆盖目录选择取消、路径就绪、运行中状态、取消、完成统计、筛选、风险项、字节格式化和可读错误。Avalonia Headless + Skia 测试覆盖最小窗口加载、导航、空态和完成审核态，并输出 1280 × 780 PNG。

本地视觉复核结果：空态与完成态均无横向溢出、关键操作裁切或中文字体问题；审核列表的类型、路径、风险说明和大小信息可区分。预览输出位于 `%TEMP%/vaultdelta-ui-preview/`。
