# 配置驱动的部分目录同步界面预览

日期：2026-09-10
状态：第一版界面已落地，范围引擎尚未接入

## 目标

在不改变现有快照比较、补丁应用和回滚行为的前提下，先验证部分目录同步的操作方式。配置不绑定“家里”“公司”或具体设备，只描述一个库中需要同步的相对目录；任意电脑都可以使用同一份配置导出或接收改动，各电脑分别保存自己的本机基线。

## 推荐操作流

1. 创建或导入一份同步配置，例如“工作资料”。
2. 选择本机的 Obsidian 库，勾选配置包含的相对目录。
3. 工具把新加入的目录标记为“首次完整同步”，把本机已有基线的目录标记为“继续增量”。
4. 保存配置后，用户可以选择“导出本机改动”或“接收更新 ZIP”。
5. 每台电脑独立推进自己的本机基线，不在配置文件中写入设备角色或机器路径。

## 已落地界面

- 两个主功能统一命名为“创建更新包”和“应用更新包”，不强制强调增量实现。
- 原 248 像素左侧导航缩为 84 像素品牌轨，释放内容宽度。
- 两个主功能通过页头双段滑动开关切换，选中底板使用 200 毫秒位移动画。
- “同步范围”取消独立页签，收进“创建更新包”顶部的高级折叠区。
- 高级区用 `CD → BCD` 展示 B 首次装入、C/D 延续本机基线，但明确标为规划中。
- 配置文件只保存配置 ID、名称、包含目录、范围版本和安全策略；不保存电脑身份、绝对路径和文件基线。
- 本机状态另行保存库标识、逐目录快照、最后导入/导出序号和待确认事务。

## 本阶段验证边界

- 页面只能在“创建更新包”和“应用更新包”两个主模式之间切换。
- 最小支持窗口尺寸下两个模式和高级折叠区均可渲染并滚动。
- 高级区必须明确说明范围尚未接入补丁算法。
- 禁止让预览配置改变现有全库比较或生成结果。
- 现有拖放、比较、进度、应用和回滚测试不得回归。

## 后续实现边界

确认界面后再新增配置持久化、嵌套目录树扫描、逐目录基线、范围版本、补丁清单扩展和接收端配置校验。实现之前，界面中的示例配置、路径和基线均不是用户数据。

## 预计页面与操作

### 创建更新包

默认继续使用两个快照创建更新包。用户可展开顶部“同步范围（高级）”，未来在这里创建、导入和编辑 `.vdprofile`；选择目录后先展示范围变化，新增目录第一次完整装入，已有目录继续增量。

### 应用更新包

拖入 ZIP 并选择目标库。工具读取配置和范围，验证载荷、目标基线与路径边界，列出冲突；无冲突时事务应用。成功后更新本机基线并生成轻量回执。

### 历史与恢复

查看每份配置的导出、接收、回执和失败记录；未完成事务可以继续检查或回滚。历史记录不改变同步范围。

现有手动选择两个快照仍是稳定入口；配置驱动的部分目录比较在高级区逐步接入，不建立第三个主模式。
