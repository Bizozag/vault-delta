# 安全、冲突与失败恢复

## 1. 威胁边界

补丁包属于不受信任输入。即使由用户自己传输，也可能因介质损坏、误替换或恶意修改而变化。目标库属于高价值数据，Apply 必须按文件更新事务处理，而不是普通批量复制。

## 2. 主要威胁与控制

| 威胁 | 控制 |
|---|---|
| Zip Slip / 路径穿越 | 规范化路径并验证最终绝对路径仍位于 staging 或目标根 |
| 绝对路径覆盖 | Manifest 只接受 RelativePath |
| 链接跳出目标根 | 默认拒绝符号链接、目录联接点、重解析点及其他特殊条目，不跟随链接 |
| 补丁载荷被修改 | Apply 前逐文件 SHA-256 |
| 目标库存在新修改 | 基线哈希冲突，默认阻断 |
| 应用中断导致半更新 | 先备份、逐步 Journal、自动回滚 |
| 磁盘耗尽 | 修改前进行空间预算和测试写 |
| 文件被 Obsidian/杀毒软件占用 | 预检可读写性；操作失败进入回滚 |
| 恶意脚本 | Apply 只解释声明式 manifest，不执行包内脚本 |
| 大小写路径冲突 | 所有平台在生成阶段按可移植规则阻断 |

## 3. 目标端锁

目标根创建 `.vaultdelta.lock`，内容包含 operationId、进程 ID、开始时间和应用器版本。若锁存在：

- 对应进程仍活动：拒绝第二次 Apply。
- 进程不存在但 Journal 未完成：进入恢复界面。
- Journal 已提交：允许清理陈旧锁并记录。

锁不是唯一安全机制；每个操作前仍重新验证目标旧状态，防止外部程序修改。

## 4. 备份布局

```text
<vault-parent>/.vaultdelta-backups/
  <operationId>/
    journal.json
    replaced/
    deleted/
    displaced/
    logs/
```

默认放在目标库父目录，避免 Obsidian 索引备份内容。若用户指定其他位置，必须验证在本地可写文件系统且空间足够。

macOS 外接卷可能使用 APFS、HFS+、exFAT 或网络文件系统，原子替换、大小写和权限语义并不完全一致。Apply 必须按实际卷探测能力，备份与临时文件默认放在目标同卷；无法满足安全写入不变量时阻断，而不是降级为直接覆盖。

## 5. 原子写策略

修改文件时：

1. 在目标同目录创建随机临时文件。
2. 写入载荷并 flush。
3. 校验长度和哈希。
4. 备份旧文件。
5. 使用当前平台和文件系统支持的同卷原子 rename/replace 切换。

不得直接以写模式截断现有目标文件。

## 6. 冲突策略

MVP 分类：

- 安全：目标状态与基线一致。
- 警告：存在清单外额外文件。
- 冲突：受影响路径内容、类型或存在状态不一致。

冲突默认阻断整个补丁。首版不自动合并 Markdown，也不根据“较新时间戳”决定覆盖。

## 7. 回滚承诺

只要备份区和 Journal 完整，Rollback 应可多次运行并最终收敛。回滚不得依赖补丁包仍然存在。

如果备份损坏：

- 停止自动回滚。
- 保留当前文件和所有可用备份。
- 生成逐路径人工恢复报告。
- 不删除任何可能有用的中间文件。

## 8. 隐私

- 不联网。
- 不采集遥测。
- 日志默认记录路径和哈希，但不记录文件内容。
- 提供路径脱敏导出选项，方便提交问题报告。
