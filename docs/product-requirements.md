# Vault Delta 产品范围与需求

## 1. 问题定义

大型 Obsidian 笔记库只能通过文件传输在隔离环境间移动。完整库可能达到数 GB，但两个快照之间通常只有少量新增或变化。传统同步工具要求同时访问两端，而实际流程需要先在源端生成一个小型离线补丁，再将其传输到目标端并安全应用。

## 2. 用户与场景

主要用户是维护单个或少量 Obsidian 库的个人或小团队。用户具备基本文件操作能力，但不应被要求理解哈希算法、命令行参数或同步冲突模型。

典型场景：

1. 目标机器现有库对应快照 A。
2. 源机器上的库发展为快照 B。
3. 用户在可同时访问 A 和 B 的环境中生成补丁。
4. 用户只传输补丁文件。
5. 用户在目标机器上应用补丁，使目标库达到 B。

## 3. MVP 功能范围

### 3.1 必须支持

- 选择旧快照、新快照和补丁输出位置。
- 递归枚举文件，并保持相对路径。
- 支持新增、修改、删除和重命名分类。
- 支持按路径、扩展名、隐藏文件和 Obsidian 预设进行排除。
- 使用大小、时间戳和哈希的分层比较策略。
- 提供差异审核列表、数量和预计传输大小。
- 默认生成 ZIP 包；可选保留目录包用于检查、调试或受限环境传输。
- 补丁包包含载荷文件、清单和说明；平台应用程序单独发布，补丁内不嵌入可执行文件。
- 目标端应用前执行基线预检。
- 覆盖、删除和重命名前创建可恢复备份。
- 应用后验证所有受影响文件。
- 失败后自动回滚，输出结构化日志。
- 支持中文、Unicode、空格、Windows 长路径，以及 Windows/macOS 的路径和文件系统差异。
- Windows 与 macOS 桌面端共享同一核心工作流。
- macOS 同时提供 Apple Silicon (`osx-arm64`) 和 Intel (`osx-x64`) 发布物。

### 3.2 暂不支持

- 实时同步、网络传输或云端存储。
- 多人并发编辑合并。
- Markdown 语义合并或 Git 风格三方合并。
- Obsidian 插件内嵌运行。
- Linux 正式验收。
- 面向用户的无 UI 命令行应用模式；核心工作流保持 UI 无关，为后续 CLI 预留复用能力。
- 去重存储、块级差分或二进制增量编码。
- 自动定时任务。

## 4. 成功标准

- 对同一输入重复扫描，输出差异集合顺序和内容一致。
- 生成器不修改任何输入目录。
- 无删除/重命名的复制型补丁可通过拖拽合并完成更新。
- 精确型补丁应用后，受管理范围内的目标树与新快照哈希一致。
- 在任意应用阶段注入失败，目标端可恢复到应用前状态。
- 10 万文件、100 GB 级目录可完成扫描，内存不随文件内容总量线性增长。
- 所有破坏性操作在执行前均可预览，并拥有备份或明确阻断。
- Windows 和 macOS 对同一合法输入生成语义一致的 manifest 与 DiffSet。
- `osx-arm64` 与 `osx-x64` 均能形成有效 `.app` 发布物，正式公开分发版本完成签名与公证。

## 5. 非功能需求

### 性能

- 目录枚举：本地 SSD 上目标不少于 30,000 个文件/分钟。
- 未变化文件优先通过大小和时间戳快速排除。
- 内容哈希采用流式读取，单文件内存占用不超过 8 MiB 缓冲区。
- UI 在扫描期间保持响应，可暂停或取消。
- 大小写、Unicode 规范化、路径分隔符和卷类型差异不得改变 manifest 的可移植语义。

### 可靠性

- 补丁生成采用临时目录，全部完成后原子重命名为最终产物。
- 应用采用事务日志；每完成一步即持久化状态。
- RPO：受工具影响的文件为 0；覆盖前必须备份。
- RTO：失败后应能在一次回滚操作中恢复。

### 安全

- 所有相对路径必须规范化并验证不能逃逸目标根目录。
- 拒绝绝对路径、Windows 盘符/UNC 路径和 `..` 越界。
- 默认不跟随符号链接、目录联接点、重解析点或其他特殊文件系统条目。
- 补丁清单和载荷必须通过哈希验证。
- 应用器不得执行补丁包中的任意脚本或外部命令。

### 可维护性

- 核心引擎不依赖 UI。
- 模块间通过不可变模型和接口通信。
- JSON 格式包含 `schemaVersion` 并定义兼容策略。
- 单元测试覆盖纯逻辑，集成测试使用临时目录，端到端测试使用固定样例库。

## 6. 已确认的产品决策

- `.obsidian/plugins/**` 默认包含在受管理范围内。
- `.trash/**` 默认排除。
- ZIP 是默认传输产物；目录形式作为低成本的高级/调试选项保留。
- MVP 不开发面向用户的 CLI，以避免额外的命令设计、文档和验收成本。
- MVP 正式支持 Windows 与 macOS。
- 技术基线为 C#、.NET 10 LTS 与 Avalonia。
- macOS 发布 `osx-arm64` 和 `osx-x64`；Avalonia 后端负责 Metal/OpenGL 渲染，不创建独立产品版本。

## 7. 发布前仍需确认

- Windows 最低支持版本。
- macOS 最低支持版本。
- 是否已有 Apple Developer Program 账号及 Developer ID 证书用于签名和公证。
- 是否需要在 MVP 后补充 Windows ARM64 发布物。
