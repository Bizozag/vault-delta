# 端到端工作流与阶段验证门禁

## 1. 门禁模型

每个阶段由四部分组成：

- **前置条件**：允许开始阶段的条件。
- **产物**：阶段唯一允许产生的结果。
- **不变量验证**：结果必须满足的规则。
- **失败边界**：失败后允许保留和必须清理的状态。

只有 Gate 通过才能进入下一阶段。取消视为受控失败，不得自动跨过 Gate。

## 2. 补丁生成工作流

### Gate G0：会话输入验证

前置条件：

- 旧快照、新快照存在且可读。
- 两者不是同一路径，且互不包含。
- 输出目录不位于任一输入根目录内。
- 文件系统有足够权限。

验证：

- 路径解析为规范绝对路径。
- 根路径比较使用当前平台语义，补丁内部路径额外执行跨平台可移植性校验。
- 检测符号链接、重解析点和不支持的文件系统对象。

阻断条件：路径重叠、输入不可读、输出会污染快照。

### Gate G1：旧快照清单完成

产物：`BaseInventory`。

验证：

- 所有条目相对路径合法且唯一。
- 过滤规则有完整统计。
- 不存在大小写折叠碰撞或 Unicode 规范化碰撞。
- 不稳定或不可读条目为零，或已由用户明确排除。

失败边界：只保留诊断日志，不产生可复用快照清单。

### Gate G2：新快照清单完成

规则与 G1 相同，并额外验证规则版本与旧快照一致，避免比较范围不一致。

### Gate G3：差异分类完成

产物：`DiffSet`。

验证：

- Added、Modified、Deleted、Renamed 集合互斥。
- 所有新内容来源路径存在。
- 所有删除/重命名旧路径存在于 BaseInventory。
- 重命名仅由唯一哈希匹配产生。
- 操作应用后的逻辑树与 TargetInventory 等价。

阻断条件：目标路径冲突、类型冲突未被显式表达、哈希计算失败。

### Gate G4：用户审核完成

产物：`ApprovedDiffSet`。

用户必须能看到：

- 传输文件数和字节数。
- 删除和重命名数量。
- 被排除文件数及规则。
- 高风险项：类型变化、超大文件、Obsidian 配置文件。

验证：

- 取消选择操作后重新计算结果树。
- 若用户取消某个删除或修改，界面明确提示目标将不再完全等同新快照。
- “精确同步”模式不允许产生逻辑不完整的操作集合。

### Gate G5：空间与输出预检

验证：

- staging 空间不少于载荷大小 + 10% + 64 MiB。
- 默认 ZIP 模式额外预留未压缩载荷空间；目录模式执行相同内容校验。
- 输出最终名称不存在；若存在必须选择新名称，不自动覆盖。
- 当前 Vault Delta Desktop 版本与 manifest schema 兼容。

### Gate G6：载荷构建完成

产物：`files/` staging。

验证：

- 所有载荷复制后长度、SHA-256 与新快照匹配。
- files 下不存在清单外文件。
- 复制期间源文件未变化。

失败边界：最终路径不可见；staging 标记失败并清理。

### Gate G7：清单封装完成

验证：

- JSON schema 校验通过。
- 操作序号稳定且唯一。
- 所有文件操作引用的 payload 存在。
- 无绝对路径和路径逃逸。
- 包摘要与内容一致。

### Gate G8：发布验证

目录包：staging 原子重命名后重新 Inspect。

ZIP 包：关闭压缩流后重新打开，逐项验证清单和载荷哈希。

成功产物：只有通过 Inspector 的包才显示“补丁已就绪”。

## 3. 补丁应用工作流

### Gate A0：目标与补丁输入验证

- 补丁可读取，目标库存在且可写。
- 补丁不位于目标库内部。
- 目标库没有未完成的 Vault Delta Journal。
- 获取目标根独占锁。
- 当前卷支持所需的备份、临时文件和替换语义；否则在写入前阻断。

### Gate A1：补丁完整性验证

- schema 支持。
- manifest 格式和操作图合法。
- 所有 payload 哈希正确。
- 包内没有未声明文件、路径越界或可执行注入。

任何失败均视为补丁损坏或不受信任，禁止继续。

### Gate A2：目标基线验证

至少验证所有将被修改、删除和重命名的旧内容。

结果：

- Pass：可继续。
- Warning：只有额外的未管理文件，可继续但记录。
- Conflict：内容、类型或预期存在性不符，默认阻断。

MVP 不提供“强制覆盖冲突”快捷按钮。若未来增加，必须为单文件逐项确认并仍先备份。

### Gate A3：恢复能力验证

- 备份目录可创建并位于同一卷，优先支持原子移动。
- 可用空间满足所有旧内容备份 + 新内容临时写入 + 10%。
- Journal 可创建、flush 和重新读取。
- 测试写入临时文件后立即删除。

未通过则目标库保持零修改。

### Gate A4：执行计划冻结

将最终操作顺序、旧哈希、载荷哈希、备份路径写入 Journal。Journal 状态为 `Prepared`，并 flush 后才能修改目标。

### Gate A5：逐操作提交

每个操作执行流程：

1. 验证当前目标仍符合计划中的旧状态。
2. 备份旧条目。
3. Journal 记录 `BackupCompleted`。
4. 写入或移动新条目。
5. 验证新状态。
6. Journal 记录 `OperationCompleted`。

在第 1 步发现外部变化立即停止；在其余步骤失败进入 NeedsRollback。

### Gate A6：最终一致性验证

- 所有受管理目标路径与 manifest 目标哈希一致。
- 所有删除路径不存在于目标根。
- 所有重命名旧路径不存在，新路径存在。
- 清单外文件没有被工具修改。

验证失败进入 NeedsRollback，不能标记成功。

### Gate A7：事务提交

- Journal 标记 `Committed`。
- 写入应用摘要。
- 释放锁。
- 保留备份目录，默认不自动永久删除。

## 4. 回滚工作流

### Gate R0：Journal 可恢复性

- Journal schema 支持。
- operationId 和目标根匹配。
- 备份条目存在且哈希正确。

### Gate R1：逆序恢复

只撤销 Journal 中明确标记完成的步骤。每个逆向操作后立即验证并记录，支持崩溃后再次运行。

### Gate R2：基线恢复验证

所有被影响路径恢复到 Apply 前记录的状态。通过后 Journal 标记 `RolledBack`。

若备份损坏，停止自动处理并输出人工恢复清单，不继续猜测。

## 5. 验证模式

| 模式 | 用途 | 边界 |
|---|---|---|
| 快速比较 | 交互式初览 | 大小/时间戳用于排除，不能直接发布补丁 |
| 内容确认 | 生成正式 DiffSet | 所有变化候选使用 SHA-256 |
| 快速基线 | 普通应用 | 验证所有受影响旧文件 |
| 严格基线 | 高价值库 | 验证全部受管理文件 |
| 最终校验 | Apply 提交前 | 验证所有目标操作结果 |

## 6. 阶段状态机

```text
Draft
  → InputsValidated
  → InventoriesReady
  → DiffReady
  → Approved
  → PackageStaged
  → PackageVerified
  → Published

Apply:
Received
  → Inspected
  → BaselineValidated
  → Prepared
  → Applying
  → Verifying
  → Committed
          ↘ NeedsRollback → RollingBack → RolledBack
```

不允许从 Applying 直接跳到 Committed，也不允许从 NeedsRollback 再继续执行剩余补丁。
